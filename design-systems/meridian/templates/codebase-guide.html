01

What Quill is, and the shape of it

In one minute

Quill reads a folder of Markdown files, wraps each one in an HTML layout, and writes a finished website to a dist/ folder that any web server can host.

You run it from the terminal: quill build makes the site once, and quill dev keeps it rebuilding while you write, with the browser refreshing itself. It is aimed at developers and technical writers who want a blog or docs site without a JavaScript framework.

Under the hood, one build pipeline does all the work. The command line starts it, the config tells it where things are, and it hands pages to two helpers: one that reads content, one that renders HTML. Plugins can hook into each step.

The words you will run into

04

Following one build from start to finish

Here is what happens between pressing Enter and seeing “Built 42 pages”. The numbers in the diagram match the steps below.

  1. Read the command

    src/cli.ts · main()

    Parses the terminal arguments and looks up build in its command table, which points to runBuild() in src/commands/build.ts.

  2. Load and check the config

    src/config/load.ts · loadConfig()

    Imports quill.config.ts and validates it against ConfigSchema. If anything is wrong, it lists every bad field and stops with exit code 2.

  3. Start the build

    src/pipeline/build.ts · build()

    Fires the config:resolved hook through runHook(), so plugins can adjust settings before any file is read.

  4. Collect the pages

    src/content/collect.ts · collectPages()

    Finds every .md file in the content folder and passes each one to parsePage(). Broken files become errors in the list, not crashes.

  5. Decide what to rebuild

    src/pipeline/graph.ts · planBuild()

    Compares each page’s content hash with .quill/cache.json. Pages that did not change, and whose layout did not change, are skipped.

  6. Render each page

    src/render/render.ts · renderPage()

    Converts the Markdown to HTML, picks the layout named in the front matter (default page), and fills its slots.

  7. Write it to disk

    src/pipeline/build.ts · writeOutput()

    Saves the page as dist/<slug>/index.html. This is the only function that writes the site.

  8. Report and exit

    src/cli.ts · main()

    Prints how many pages were built, skipped and failed. If any page failed, the process exits with code 1 so CI notices.

Good to know

quill dev runs the same steps 02–07. The difference is that src/dev/server.ts calls build() again each time a file changes, then tells the browser to reload.

05

Three habits that run through the code

Once you spot these, most files will feel familiar before you finish reading them.

A

Errors are returned, not thrown

ERRORS

Functions that can fail return a Result: either ok(value) or err(error). The caller has to check which one it got before using the value.

src/content/parse.ts · lines 18–30
export function parsePage(file: SourceFile): Result<Page> {
  const fm = readFrontMatter(file.text);

  if (!fm.ok) {
    return err(new QuillError("E_FRONTMATTER", file.path, fm.error));
  }

  return ok({
    slug: toSlug(file.path),
    meta: fm.value,
    body: stripFrontMatter(file.text),
  });
}
TypeScript · excerpt, unchanged
  1. LINES 21–23Failure is a value.A bad front matter block becomes an err that names the file; nothing is thrown.
  2. LINES 25–29Success is wrapped too.Callers unwrap ok the same way every time.
Why

One broken page should not stop the whole site from building. build() collects every err and prints them together at the end, as the README’s “Error reporting” section describes.

B

Config is checked once, at the edge

CONFIGURATION

All settings pass through one schema when Quill starts. After that, every other file trusts the Config type and never re-checks values.

src/config/schema.ts · lines 5–16
export const ConfigSchema = z.object({
  site: z.object({
    title: z.string(),
    baseUrl: z.string().url(),
  }),
  contentDir: z.string().default("content"),
  outDir: z.string().default("dist"),
  plugins: z.array(PluginSchema).default([]),
});

// Every other module imports this type, not the raw file.
export type Config = z.infer<typeof ConfigSchema>;
TypeScript · excerpt, unchanged
  1. LINES 10–11Defaults live here.No other file decides where content or output goes.
  2. LINE 16The type follows the schema.Change a rule and every caller’s types change with it.
Why

Defaults live in one place, and a typo in the user’s config fails loudly at startup instead of causing a confusing error halfway through a build.

C

Plugins join through hooks, not subclasses

EXTENSION

The core never imports a plugin. At fixed moments it calls runHook(), which passes the data through each plugin in the order the config lists them.

src/pipeline/hooks.ts · lines 8–20
export async function runHook<K extends HookName>(
  name: K,
  ctx: HookContext[K],
  plugins: Plugin[],
): Promise<HookContext[K]> {
  let current = ctx;
  for (const plugin of plugins) {
    const handler = plugin.hooks?.[name];
    if (!handler) continue;
    current = (await handler(current)) ?? current;
  }
  return current;
}
TypeScript · excerpt, unchanged
  1. LINE 17Return to change, or not.A handler that returns nothing leaves the data as it was.
Why

A plugin can change data by returning a new value, or just observe by returning nothing. The order is predictable because it is the order in the config file.

08

Going deeper

The rules the code relies on, the trade-offs it makes, and the places it surprises people. The most important: only writeOutput() writes the site.

Invariant: one function writes to dist/

Everything else returns data. If you need a new output file, route it through writeOutput() in src/pipeline/build.ts so the build graph records it.

Trade-off: incremental builds trust the cache

planBuild() skips a page when its hash and its layout’s hash are unchanged. A plugin that reads other files can therefore see stale output; delete .quill/cache.json to force a full build.

Gotcha: plugin order matters

Hooks run plugins in the order the config lists them, and each receives the previous one’s result. Swapping two plugins can change the output.
